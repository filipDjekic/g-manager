# Prepaid metered gaming

Apply Flyway V46; existing sessions remain FIXED_DURATION and metered mode is initially disabled. Enable modes and select a default in Gaming tariff settings. Metered starts require a managed Client with fresh protocol readiness and acknowledged safe lock, a registered customer, a currently valid category-compatible tariff and credit covering at least one complete billing unit. No initial debit is made. The existing wallet ledger remains the money source of truth.

The tariff price, tariff ID, tariff duration and billing unit are frozen on each session. The total is price ? started units ? unit seconds / tariff seconds, HALF_UP to two decimal places. Every tick posts only the difference from the previously charged cumulative total in the same transaction as the billing cursor. Customer ? resource ? session locking serializes starts, ticks and finishes. A unique (session, cumulative seconds) charge index provides a second duplicate guard. Financial PAYMENT/WALLET rows settle matching charges; cashflow reports count only CASH/EXTERNAL_POS receipts, so topups and consumption do not double count cash inflow.

A customer may have one active gaming session. While metered gaming is active, withdrawals/refunds of wallet topups and other wallet spending are blocked so signed coverage cannot be spent twice. Topups and positive corrections extend the funded deadline of a still-live session without an advance debit, bounded by the next conflicting station booking. They cannot revive an expired lease; credit added after expiry remains available to a new session. End and start a new session to switch stations or tariffs. Fixed duration purchases, packages and their refund rules continue unchanged.

The funded ends_at is calculated conservatively from credit at start. Each signed metered lease has no offline grace and expires no later than that funded deadline. Missing renewals end billing at the last persisted lease deadline; reconnection after expiry cannot revive the session. Backend restarts retain the billing cursor, frozen tariff and deadline. An uncertain outage interval may include the last valid lease (normally at most 30 seconds); billing never continues beyond it. A confirmed client logout settles immediately when its authenticated request reaches the server. Existing monotonic client lease enforcement, process shutdown and Windows policy remain authoritative for local locking. Validate physical power/network loss and Windows policy enforcement on a real managed station before deployment; H2 tests cannot demonstrate a physical lock.

Customers can finish only their own metered session. Staff use the existing scoped terminate action. The Windows logout confirmation ends the machine-bound session and now settles metered time. The dashboard and signed Windows telemetry display server-calculated consumption and credit; visual timers never post charges.
